# Navigation

Navigation should feel effortless.

- Current location is always visible.
- Active state is immediately recognizable.
- Navigation should remain stable across the application.
- Group related destinations logically.
- Reveal complexity progressively.

---

# Buttons

Buttons communicate intent, not importance.

- One primary action per view.
- Secondary actions should never compete visually.
- Size buttons for the content, not the container.
- Use consistent radius and spacing.
- Place actions where users naturally expect them.

Avoid oversized call-to-actions.

---

# Headers

Headers establish hierarchy.

- Let typography create emphasis.
- Keep supporting information concise.
- Avoid decorative containers.
- Actions should complement, not compete with, the title.

---

# Sections

Structure through spacing before containers.

- Prefer sections over cards.
- Group related information.
- Use dividers sparingly.
- Allow whitespace to define relationships.

The layout should feel organized without relying on visual decoration.

---

# Cards

Cards are contextual containers.

Use cards only when they:

- Group related information
- Separate independent content
- Improve comprehension

Avoid card-heavy layouts.

Cards should support the interface, not become the interface.

---

# Tables

Tables are the default for structured data.

- Prefer tables for dense datasets.
- Prefer lists when hierarchy is more important than comparison.
- Keep rows compact and scannable.
- Minimize visual separators.
- Align values consistently.
- Preserve readability over density.

---

# Forms

Forms should reduce cognitive effort.

- Group related fields.
- Use multiple columns when appropriate.
- Reveal advanced options progressively.
- Keep labels clear and concise.
- Validate inline whenever possible.

Avoid unnecessarily long forms.

---

# Search

Search should be immediately accessible.

- Place search near the content it affects.
- Support filtering and sorting naturally.
- Provide immediate feedback.
- Preserve user context while searching.

---

# Filters

Filters refine information, not navigation.

- Place filters close to the data.
- Show commonly used filters by default.
- Hide advanced filters behind progressive disclosure.
- Make active filters obvious.
- Make resetting filters effortless.

---

# Contextual Panels

Panels provide supporting context.

Use them for:

- Details
- Metadata
- Activity
- Settings
- Secondary workflows

Never interrupt the primary task.

---

# Empty States

Empty states should guide, not decorate.

- Explain why nothing is shown.
- Suggest the next logical action.
- Keep messaging concise.
- Avoid illustrations unless they communicate meaning.

---

# Actions

Actions should appear where decisions are made.

- Primary actions should be easy to discover.
- Secondary actions belong near related content.
- Destructive actions require clear differentiation.
- Reduce unnecessary confirmations.

Users should never search for the next step.

---

# Data

Data is the product.

- Prioritize information over interface.
- Optimize for scanning before reading.
- Surface the most important information first.
- Reduce visual noise around content.
- Preserve consistency across similar views.

The interface exists to reveal the data, not compete with it.
